# 数据库 Schema 与迁移

使用 RAGFlow 官方脚本同步 Schema 并迁移数据。

---

RAGFlow 会在启动时自动处理 Schema 更新和迁移。然而，在 Kubernetes 等高并发环境中，海量数据集可能导致初始化时间超过 10 分钟，从而可能触发容器超时或健康检查失败。为避免此问题，您可以禁用内置的自动初始化，并手动运行以下脚本来完成数据库升级，然后再启动服务：

- [mysql_migration.py](#mysql_migrationpy)：在 MySQL 表之间迁移数据。
- [db_schema_sync.py](#db_schema_syncpy)：同步数据库 Schema 并使用 peewee-migrate 管理变更。

## mysql_migration.py

[mysql_migration.py](https://github.com/infiniflow/ragflow/blob/main/tools/scripts/mysql_migration.py) 脚本是一个用于重组 RAGFlow 模型相关数据的专用工具。它将数据从旧的统一表迁移到现代的多表结构，以支持高级模型管理。

### 核心功能

- **顺序迁移**：通过三个不同阶段（Provider、Instance 和 Model）移动数据，以维护数据库完整性并满足依赖关系。
- **灵活配置**：可使用 YAML 配置文件或直接通过命令行参数连接 MySQL。
- **执行控制**：提供三种模式：dry-run（预览）、table-only（仅结构搭建）和 execute（完整数据迁移）。
- **自动映射**：在旧记录和新表结构之间生成唯一 ID 并处理复杂的关联。
- **批量日志**：以 100 条为一批处理记录，并提供总耗时和行数的最终汇总。

### 使用场景

- **版本升级**：升级到 RAGFlow v0.25 或更高版本时至关重要，可确保模型在新 Schema 中被正确分类。
- **数据规范化**：将多个 API 密钥或 LLM 供应商合并到更新后的系统格式时必不可少。
- **Kubernetes 部署**：使用 `--create-table-only` 标志在主服务启动前独立搭建数据库结构。
- **迁移验证**：在 dry-run 模式下使用，识别仍需迁移到新表的遗留记录。

## db_schema_sync.py

[db_schema_sync.py](https://github.com/infiniflow/ragflow/blob/main/tools/scripts/db_schema_sync.py) 脚本是一个同步工具，确保您的 MySQL 数据库结构与 RAGFlow 源码中定义的 Peewee ORM 模型保持一致。

### 核心功能

- **变更检测**：将 `api/db/db_models.py` 中的 Python 模型定义与运行中的数据库进行比较，识别新表、新增字段或类型不匹配。
- **迁移生成**：自动在版本特定的目录（例如 `tools/migrate/v0_25_0/`）中创建 Python 迁移文件（包含 `migrate()` 和 `rollback()` 逻辑）。
- **Schema 审计**：提供 `--diff` 命令来查看结构差异，而无需应用更改。
- **执行管理**：将待处理的迁移应用到数据库，使其与当前软件版本保持同步。
- **安全控制**：要求使用显式的 `--drop` 标志为已删除字段生成 `DROP COLUMN` 语句，防止意外数据丢失。

### 使用场景

- **版本升级**：升级到引入数据库结构变更的新版 RAGFlow 时使用。
- **开发**：当修改 `db_models.py` 并需要更新本地数据库而无需手动编写 SQL 时使用。
- **CI/CD 流水线**：在部署过程中自动准备或应用数据库更新。
- **故障排除**：当应用因"Unknown column"或"Table not found"错误而失败时，说明 Schema 已不同步。
