## 数据迁移

:::info 致谢
本文档由社区贡献者 [TreeDy](https://github.com/Treedy2020) 贡献。我们可能不会积极维护此文档。
:::

一个常见场景是：在强性能实例（例如带 GPU）上处理大型数据集，然后将整个 RAGFlow 服务迁移到另一个生产环境（例如纯 CPU 服务器）。本指南说明如何使用我们提供的迁移脚本安全地备份和恢复数据。

### 确认您的数据

默认情况下，RAGFlow 使用 Docker 卷存储所有持久化数据，包括数据库、上传的文件和搜索索引。您可以通过运行以下命令查看这些卷：

```bash
docker volume ls
```

输出大致如下：

```text
DRIVER    VOLUME NAME
local     docker_esdata01
local     docker_minio_data
local     docker_mysql_data
local     docker_redis_data
```

这些卷包含了您需要迁移的所有数据。

:::note
卷名称前缀（例如 `docker_`）来自 Docker Compose 项目名称。默认情况下是 `docker`（源自目录名称）。如果您使用 `docker compose -p <project_name>` 启动 RAGFlow，卷的前缀将是 `<project_name>_`，例如 `ragflow_mysql_data`。
:::

### 第 1 步：停止 RAGFlow 服务

在开始迁移之前，您必须停止**源机器**上所有正在运行的 RAGFlow 服务。导航到项目根目录并运行：

```bash
docker compose -f docker/docker-compose.yml down
```

如果您使用自定义项目名称启动 RAGFlow（例如 `docker compose -p ragflow`），请在命令中包含它：

```bash
docker compose -p ragflow -f docker/docker-compose.yml down
```

**注意：** 请**不要**使用 `-v` 标志（例如 `docker compose down -v`），因为这会删除所有数据卷。迁移脚本包含检查机制，如果检测到服务仍在运行，将阻止您执行迁移。

### 第 2 步：备份数据

我们提供了一个便捷脚本，将所有数据卷打包到一个备份文件夹中。

要快速查看脚本的命令和选项，可以运行：
```bash
bash docker/migration.sh help
```

要创建备份，请从项目根目录运行以下命令：

```bash
bash docker/migration.sh backup
```

这将在项目根目录创建一个 `backup/` 文件夹，其中包含数据卷的压缩归档。

您也可以为备份文件夹指定自定义名称：

```bash
bash docker/migration.sh backup my_ragflow_backup
```

这将创建一个名为 `my_ragflow_backup/` 的文件夹。

如果您使用自定义项目名称启动 RAGFlow（例如 `docker compose -p ragflow`），请使用 `-p` 标志以便脚本找到正确的卷：

```bash
bash docker/migration.sh -p ragflow backup
bash docker/migration.sh -p ragflow backup my_ragflow_backup
```

### 第 3 步：传输备份文件夹

将整个备份文件夹（例如 `backup/` 或 `my_ragflow_backup/`）从源机器复制到**目标机器**上的 RAGFlow 项目目录中。您可以使用 `scp`、`rsync` 或物理驱动器等工具进行传输。

### 第 4 步：恢复数据

在**目标机器**上，确保 RAGFlow 服务未运行。然后，使用迁移脚本从备份文件夹恢复数据。

如果备份文件夹名为 `backup/`，运行：

```bash
bash docker/migration.sh restore
```

如果您使用了自定义名称，请在命令中指定：

```bash
bash docker/migration.sh restore my_ragflow_backup
```

如果目标机器使用自定义项目名称，请使用 `-p` 标志以确保使用正确的前缀创建卷：

```bash
bash docker/migration.sh -p ragflow restore
bash docker/migration.sh -p ragflow restore my_ragflow_backup
```

脚本将自动创建必要的 Docker 卷并解包数据。

**注意：** 如果脚本检测到目标机器上已存在同名 Docker 卷，将警告您恢复会覆盖现有数据，并在继续前请求确认。

### 第 5 步：启动 RAGFlow 服务

恢复过程完成后，可以在新机器上启动 RAGFlow 服务：

```bash
docker compose -f docker/docker-compose.yml up -d
```

如果使用自定义项目名称：

```bash
docker compose -p ragflow -f docker/docker-compose.yml up -d
```

**注意：** 如果您之前已经通过 docker compose 构建了服务，可能需要像上述指南一样备份目标机器的数据，然后运行：

```bash
# 在执行以下命令前，请先通过 `bash docker/migration.sh backup backup_dir_name` 进行备份。
# !!! 以下命令中的 -v 标志将删除原有的 Docker 卷
docker compose -f docker/docker-compose.yml down -v
docker compose -f docker/docker-compose.yml up -d
```

您的 RAGFlow 实例现在已在新机器上运行，并带有原始机器的所有数据。

## 从多桶模式迁移到单桶模式

:::info 致谢
本文档由社区贡献者 [arogan178](https://github.com/arogan178) 贡献。我们可能不会积极维护此文档。
:::

默认情况下，RAGFlow 为每个知识库（数据集）创建一个桶，为每个用户文件夹创建一个桶。这在以下情况下可能会带来问题：

- 您的云服务商按桶计费
- 您的 IAM 策略限制桶的创建
- 您希望所有数据组织在单个桶中，使用目录结构

**单桶模式**允许您将 RAGFlow 配置为使用单个桶加目录结构，而非多个桶。

### 工作原理

#### 默认模式（多桶）

```
bucket: kb_12345/
  └── document_1.pdf
bucket: kb_67890/
  └── document_2.pdf
bucket: folder_abc/
  └── file_3.txt
```

#### 单桶模式（含 prefix_path）

```
bucket: ragflow-bucket/
  └── ragflow/
      ├── kb_12345/
      │   └── document_1.pdf
      ├── kb_67890/
      │   └── document_2.pdf
      └── folder_abc/
          └── file_3.txt
```

### 配置

#### MinIO 配置

编辑您的 `service_conf.yaml` 或设置环境变量：

```yaml
minio:
  user: "your-access-key"
  password: "your-secret-key"
  host: "minio.example.com:443"
  bucket: "ragflow-bucket" # 默认桶名称
  prefix_path: "ragflow" # 可选前缀路径
```

或使用环境变量：

```bash
export MINIO_USER=your-access-key
export MINIO_PASSWORD=your-secret-key
export MINIO_HOST=minio.example.com:443
export MINIO_BUCKET=ragflow-bucket
export MINIO_PREFIX_PATH=ragflow
```

#### S3 配置（已支持）

```yaml
s3:
  access_key: "your-access-key"
  secret_key: "your-secret-key"
  endpoint_url: "https://s3.amazonaws.com"
  bucket: "my-ragflow-bucket"
  prefix_path: "production"
  region: "us-east-1"
```

### IAM 策略示例

使用单桶模式时，您只需要一个桶的权限：

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:*"],
      "Resource": [
        "arn:aws:s3:::ragflow-bucket",
        "arn:aws:s3:::ragflow-bucket/*"
      ]
    }
  ]
}
```

### 从多桶迁移到单桶

如果要从多桶模式迁移到单桶模式：

1. 为新的配置**设置环境变量**
2. **重启** RAGFlow 服务
3. （可选）**迁移现有数据**：

```bash
# 使用 mc（MinIO Client）的示例
mc alias set old-minio http://old-minio:9000 ACCESS_KEY SECRET_KEY
mc alias set new-minio https://new-minio:443 ACCESS_KEY SECRET_KEY

# 列出所有知识库桶
mc ls old-minio/ | grep kb_ | while read -r line; do
    bucket=$(echo $line | awk '{print $5}')
    # 将每个桶复制到新结构
    mc cp --recursive old-minio/$bucket/ new-minio/ragflow-bucket/ragflow/$bucket/
done
```

### 模式切换

#### 启用单桶模式

```yaml
minio:
  bucket: "my-single-bucket"
  prefix_path: "ragflow"
```

#### 禁用（使用多桶模式）

```yaml
minio:
  # 将 bucket 和 prefix_path 留空或注释掉
  # bucket: ''
  # prefix_path: ''
```

### 故障排除

#### 问题：Access Denied 错误

**解决方案**：确保您的 IAM 策略授予了对配置中指定桶的访问权限。

#### 问题：切换模式后找不到文件

**解决方案**：不同模式之间的路径结构会发生变化，需要迁移现有数据。

#### 问题：HTTPS 连接失败

**解决方案**：确保 MinIO 连接中设置了 `secure: True`（对于 443 端口会自动处理）。

### 支持的存储后端

- ✅ **MinIO** - 全面支持单桶模式
- ✅ **AWS S3** - 全面支持单桶模式
- ✅ **阿里云 OSS** - 全面支持单桶模式
- ✅ **Azure Blob** - 使用基于容器的结构（不同范式）
- ⚠️ **OpenDAL** - 取决于底层存储后端

### 性能考虑

- **单桶模式**：在桶列表操作方面性能可能略好
- **多桶模式**：在大型部署中提供更好的隔离性和组织结构
- 请根据您的具体需求和基础设施约束进行选择
