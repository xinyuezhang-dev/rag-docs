# 贡献指南

RAGFlow 社区贡献者通用指南。

---

本文档提供向 RAGFlow 提交贡献的指南和主要注意事项。

- 要报告 Bug，请提交 [GitHub issue](https://github.com/infiniflow/ragflow/issues/new/choose)。
- 如有进一步问题，您可以在 [Discussions](https://github.com/orgs/infiniflow/discussions) 中查看现有讨论或发起新讨论。

## 您可以贡献什么

以下列表列出了一些您可以做的贡献，但并非完整列表。

- 提出或实现新功能
- 修复 Bug
- 添加测试用例或演示
- 发布博客或教程
- 更新现有文档、代码或注释
- 建议更友好的错误码

## 提交 Pull Request (PR)

### 通用流程

1. Fork 我们的 GitHub 仓库。
2. 将 fork 克隆到本地：
`git clone git@github.com:<yourname>/ragflow.git`
3. 创建本地分支：
`git checkout -b my-branch`
4. 在提交信息中提供充分的说明
`git commit -m '在提交信息中提供充分的说明'`
5. 将更改提交到本地分支，并推送到 GitHub：
`git push origin my-branch`
6. 提交 Pull Request 以供审核。

### 提交 PR 前

- 考虑将较大的 PR 拆分为多个较小的、独立的 PR，以保持可追溯的开发历史。
- 确保您的 PR 只针对一个问题，或将不相关的更改控制在较小范围。
- 贡献新功能时请添加测试用例。它们能证明您的代码功能正确，并防止未来更改带来的潜在问题。

### 描述您的 PR

- 确保 PR 标题简洁明了，提供所有必要信息。
- 如适用，在 PR 描述中引用相应的 GitHub issue。
- 对于*破坏性变更*或*API 变更*，请在描述中包含足够的设计细节。

### 审核与合并 PR

确保您的 PR 在合并前通过所有持续集成 (CI) 测试。
