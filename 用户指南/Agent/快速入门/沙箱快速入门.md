# Sandbox 快速入门

一个安全、可插拔的代码执行后端，专为 RAGFlow 以及其他需要隔离代码执行环境的应用而设计。

RAGFlow 的 `CodeExec` Agent 组件依赖 Sandbox 提供者来运行 Python 和 JavaScript 代码。在使用 `CodeExec` 之前，请先配置以下提供者之一。

## 功能特性：

- 无缝 RAGFlow 集成——与 RAGFlow 的 Code 组件开箱即用。
- 高安全性——使用 gVisor 进行系统调用级沙箱隔离。
- 可定制沙箱——轻松修改 seccomp 配置文件以定制系统调用限制。
- 可插拔运行时支持——可扩展支持任何编程语言运行时。
- 开发者友好——通过便捷的 Makefile 快速设置。

## 架构

该架构由各语言运行时的隔离 Docker 基础镜像组成，由 executor manager 服务统一管理。executor manager 使用 gVisor 进行系统调用拦截，并通过可选的 seccomp 配置文件增强系统调用过滤，编排沙箱化的代码执行。

## 提供者选项

RAGFlow 支持两种 Sandbox 提供者类型：

- `self_managed`：在 Docker 管理的沙箱容器中运行代码。用于标准 RAGFlow Sandbox 部署。
- `local`：作为本地 Python 或 Node.js 子进程运行代码。仅在受信任的开发环境中使用。

## 前提条件

- 与 gVisor 兼容的 Linux 发行版。
- 已安装并配置 gVisor。
- Docker 版本 25.0 或更高（API 1.44+）。确保 executor manager 镜像搭载 Docker CLI `29.1.0` 或更高版本，以与最新的 Docker 守护进程保持兼容。
- Docker Compose 版本 2.26.1 或更高（与 RAGFlow 要求类似）。
- uv 包和项目管理器已安装。
- （可选）GNU Make，用于简化的命令行管理。

:::tip 注意
错误信息 `client version 1.43 is too old. Minimum supported API version is 1.44` 表示 executor manager 镜像内置的 Docker CLI 版本低于当前 Docker 守护进程所需的 `29.1.0`。
:::

## 构建 Docker 基础镜像

Sandbox 使用隔离的基础镜像来提供安全的容器化执行环境。

### 方案一：从源码构建

构建运行时基础镜像：

```bash
docker build -t sandbox-base-python:latest ./sandbox_base_image/python
docker build -t sandbox-base-nodejs:latest ./sandbox_base_image/nodejs
```

也可以使用 Makefile 一次性构建所有基础镜像：

```bash
make build
```

构建 executor manager 镜像：

```bash
docker build -t sandbox-executor-manager:latest ./executor_manager
```

### 方案二：从 Docker Hub 拉取基础镜像

如果不需要自定义运行时依赖，可以拉取已发布的基础镜像并标记为独立 Docker Compose 使用的名称：

```bash
docker pull infiniflow/sandbox-base-python:latest
docker pull infiniflow/sandbox-base-nodejs:latest

docker tag infiniflow/sandbox-base-python:latest sandbox-base-python:latest
docker tag infiniflow/sandbox-base-nodejs:latest sandbox-base-nodejs:latest
```

然后重启独立 Sandbox 服务：

```bash
docker compose -f docker-compose.yml down
docker compose -f docker-compose.yml up -d
```

## 与 RAGFlow 一起运行

1. 验证 gVisor 已正确安装并可用。

2. 配置位于 `docker/.env` 的 .env 文件：

- 设置 `SANDBOX_ENABLED=1`。
- 设置 `SANDBOX_PROVIDER_TYPE=self_managed` 或 `SANDBOX_PROVIDER_TYPE=local`。
- 对于 `self_managed`，在 `COMPOSE_PROFILES` 中包含 `sandbox`。
- 对于 `local`，取消注释并调整 `SANDBOX_LOCAL_*` 变量。

3. 在 `/etc/hosts` 文件中添加以下条目以解析 executor manager 服务：

    ```bash
    127.0.0.1 es01 infinity mysql minio redis sandbox-executor-manager
    ```

4. 照常启动 RAGFlow 服务。

## 环境变量

`docker/.env` 中的变量按作用域分组。

### 共享变量

这些变量适用于 Sandbox 支持的通用设置：

- `SANDBOX_ENABLED`：在 RAGFlow 中启用 Sandbox 支持。
- `SANDBOX_PROVIDER_TYPE`：选择活动提供者。支持的值为 `self_managed` 和 `local`。
- `SANDBOX_HOST`：self-managed 提供者和传统 HTTP 回退使用的 executor manager 主机地址。
- `SANDBOX_ARTIFACT_BUCKET`：用于存储 Sandbox 代码生成文件的 MinIO 存储桶。
- `SANDBOX_ARTIFACT_EXPIRE_DAYS`：Sandbox 产物过期前的天数。

### Self-managed 变量

这些变量在 `SANDBOX_PROVIDER_TYPE=self_managed` 时生效：

- `COMPOSE_PROFILES`：必须包含 `sandbox` 才能与 RAGFlow 一起启动 `sandbox-executor-manager`。
- `SANDBOX_EXECUTOR_MANAGER_IMAGE`：executor manager 服务的 Docker 镜像。
- `SANDBOX_EXECUTOR_MANAGER_POOL_SIZE`：池中保持的 Python 和 Node.js Sandbox 容器数量。
- `SANDBOX_BASE_PYTHON_IMAGE`：executor 管理的容器使用的 Python 运行时镜像。
- `SANDBOX_BASE_NODEJS_IMAGE`：executor 管理的容器使用的 Node.js 运行时镜像。
- `SANDBOX_EXECUTOR_MANAGER_PORT`：executor manager 暴露的宿主机端口。
- `SANDBOX_ENABLE_SECCOMP`：为 Sandbox 容器启用可选的 seccomp 配置文件。
- `SANDBOX_MAX_MEMORY`：每个 Sandbox 运行时容器的内存限制。
- `SANDBOX_TIMEOUT`：默认执行超时时间。

### Local 变量

这些变量在 `SANDBOX_PROVIDER_TYPE=local` 时生效：

- `SANDBOX_LOCAL_ENABLED`：显式启用本地代码执行。
- `SANDBOX_LOCAL_PYTHON_BIN`：本地执行使用的 Python 可执行文件。
- `SANDBOX_LOCAL_NODE_BIN`：本地执行使用的 Node.js 可执行文件。
- `SANDBOX_LOCAL_WORK_DIR`：本地执行文件和产物的工��目录。
- `SANDBOX_LOCAL_TIMEOUT`：本地最大执行时间（秒）。
- `SANDBOX_LOCAL_MAX_MEMORY_MB`：本地子进程的地址空间内存限制。
- `SANDBOX_LOCAL_MAX_OUTPUT_BYTES`：stdout 和 stderr 的最大大小。
- `SANDBOX_LOCAL_MAX_ARTIFACTS`：执行后收集的最大产物数量。
- `SANDBOX_LOCAL_MAX_ARTIFACT_BYTES`：每个产物的最大大小。
- `OPENBLAS_NUM_THREADS`、`OMP_NUM_THREADS`、`MKL_NUM_THREADS`、`NUMEXPR_NUM_THREADS`、`BLIS_NUM_THREADS`、`VECLIB_MAXIMUM_THREADS`：本地 Python 子进程的可选原生数学库线程限制。

## 独立运行

### 手动设置

1. 初始化环境变量：

    ```bash
    cp .env.example .env
    ```

2. 使用 Docker Compose 启动 Sandbox 服务：

    ```bash
    docker compose -f docker-compose.yml up
    ```

3. 测试 Sandbox 设置：

    ```bash
    source .venv/bin/activate
    export PYTHONPATH=$(pwd)
    uv pip install -r executor_manager/requirements.txt
    uv run tests/sandbox_security_tests_full.py
    ```

### 使用 Makefile

通过一条命令运行全部设置、构建、启动和测试：

```bash
make
```

### 监控

查看 executor manager 容器的日志：

```bash
docker logs -f sandbox-executor-manager
```

或使用 Makefile 快捷命令：

```bash
make logs
```
