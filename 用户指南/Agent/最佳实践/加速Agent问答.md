# 加速问答

加快问答速度的检查清单。

---

请注意，某些设置可能会消耗大量时间。如果您经常发现问答耗时较长，可以参考以下检查清单：

## 在任务复杂度与 Agent 性能和速度之间取得平衡

Agent 的响应时间通常取决于许多因素，如 LLM 的能力和提示词，后者反映了任务的复杂度。使用 Agent 时，应始终在任务需求与 LLM 能力之间取得平衡。

- 对于简单任务，如检索、重写、格式化或结构化数据提取，使用简洁的提示词，移除规划或推理指令，强制限制输出长度，选择较小的或 Turbo 级别的模型。这可以在对质量影响最小的情况下显著降低延迟和成本。

- 对于复杂任务，如多步推理、跨文档综合或基于工具的工作流，保持或增强包含规划、反思和验证步骤的提示词。

- 在多 Agent 编排系统中，将简单子任务委派给使用较小、较快模型的子 Agent，将更强大的模型保留给主导 Agent 来处理复杂性和不确定性。

:::tip 关键洞察
重点放在最小化输出 token 上——通过摘要、要点或明确的长度限制——这比优化输入大小对降低延迟的影响要大得多。
:::

## 禁用推理

禁用**推理**开关将减少 LLM 的思考时间。对于 Qwen3 等模型，还需要在系统提示词中添加 `/no_think` 来禁用推理。

## 禁用重排序模型

- 将 **Rerank model** 字段留空（在相应的 **Retrieval** 组件中）将显著减少检索时间。
- 使用重排序模型时，请确保有 GPU 进行加速；否则重排序过程会*极其*缓慢。

:::tip 注意
请注意，重排序模型在某些场景下是必需的。速度和性能之间总是存在权衡；您必须根据具体情况进行利弊权衡。
:::

## 检查每项任务的耗时

点击*当前*对话上方的灯泡图标，向下滚动弹出窗口查看每项任务的耗时：

| 项目名称           | 描述                                       |
|-------------------|-------------------------------------------|
| Total             | 本轮对话的总耗时，包括分块检索和回答生成。       |
| Check LLM         | 验证指定 LLM 的耗时。                        |
| Create retriever  | 创建分块检索器的耗时。                        |
| Bind embedding    | 初始化嵌入模型实例的耗时。                     |
| Bind LLM          | 初始化 LLM 实例的耗时。                       |
| Tune question     | 使用多轮对话上下文优化用户查询的耗时。           |
| Bind reranker     | 为分块检索初始化重排序模型实例的耗时。           |
| Generate keywords | 从用户查询中提取关键词的耗时。                  |
| Retrieval         | 检索分块的耗时。                              |
| Generate answer   | 生成回答的耗时。                              |
