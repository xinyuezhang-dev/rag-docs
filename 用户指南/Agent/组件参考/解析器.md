# Parser 组件

为数据集设置解析规则的组件。

---

**Parser** 组件会自动出现在数据摄入管道画布上，是所有数据摄入管道工作流中的必需组件。就像传统 ETL 流程中的**提取（Extract）**阶段一样，数据摄入管道中的 **Parser** 组件定义如何将各种文件类型解析为结构化数据。点击该组件显示其配置面板。在此配置面板中，您可以为各种文件类型设置解析规则。

## 配置说明

在配置面板中，您可以添加多个解析器并设置相应的解析规则，或移除不需要的解析器。请确保您的解析器集合覆盖了所有需要的文件类型；否则，在数据集的 **Files** 页面上选择该数据摄入管道时会出现错误。

**Parser** 组件支持解析以下文件类型：

| 文件类型         | 文件格式                      |
|-----------------|------------------------------|
| PDF             | PDF                          |
| 电子表格         | XLSX、XLS、CSV                |
| 图片            | PNG、JPG、JPEG、GIF、TIF      |
| 邮件            | EML                          |
| 文本与标记       | TXT、MD、MDX、HTML、JSON      |
| Word            | DOCX                         |
| PowerPoint      | PPTX、PPT                     |
| 音频            | MP3、WAV                      |
| 视频            | MP4、AVI、MKV                 |

### 检测多栏布局

优化解析器以检测多栏页面并将其重排序为逻辑顺序。非常适合双栏或报纸风格排版的 PDF 文档。

### 移除原始目录

去除 PDF 文件的原始目录。启用后，目录不会被分块或解析用于检索。

### PDF 解析器

PDF 解析器的输出为 `json`。在 PDF 解析器中，您可以选择最适合您的 PDF 的解析方法。

- DeepDoc：（默认）默认的视觉模型，对复杂 PDF 执行 OCR、TSR 和 DLR 任务，但可能比较耗时。
- Naive：如果*所有* PDF 都是纯文本的，可以跳过 OCR、TSR 和 DLR 任务。
- [MinerU](https://github.com/opendatalab/MinerU)：（实验性）一个将 PDF 转换为机器可读格式的开源工具。
- [Docling](https://github.com/docling-project/docling)：（实验性）一个面向生成式 AI 的开源文档处理工具。
- 来自特定模型提供商的第三方视觉模型。

:::danger 重要
从 v0.22.0 开始，RAGFlow 包含 MinerU（&ge; 2.6.3）作为可选的多后端 PDF 解析器。请注意，RAGFlow 仅作为 MinerU 的*远程客户端*，调用 MinerU API 解析文档并读取返回的文件。要使用此功能：
:::

1. 准备一个可访问的 MinerU API 服务（FastAPI 服务器）。
2. 在 **.env** 文件中或通过 UI 的 **Model providers** 页面，将 RAGFlow 配置为 MinerU 的远程客户端：
   - `MINERU_APISERVER`：MinerU API 端点（如 `http://mineru-host:8886`）。
   - `MINERU_BACKEND`：MinerU 后端：
      - `"pipeline"`（默认）
      - `"vlm-http-client"`
      - `"vlm-transformers"`
      - `"vlm-vllm-engine"`
      - `"vlm-mlx-engine"`
      - `"vlm-vllm-async-engine"`
      - `"vlm-lmdeploy-engine"`。
   - `MINERU_SERVER_URL`：（可选）下游 vLLM HTTP 服务器（如 `http://vllm-host:30000`）。当 `MINERU_BACKEND` 设置为 `"vlm-http-client"` 时适用。
   - `MINERU_OUTPUT_DIR`：（可选）存放 MinerU API 服务输出文件（zip/JSON）的本地目录，用于数据摄入前。
   - `MINERU_DELETE_OUTPUT`：使用临时目录时是否删除临时输出：
     - `1`：删除。
     - `0`：保留。
3. 在 Web UI 中，导航到数据集的 **Configuration** 页面，找到 **Ingestion pipeline** 部分：
   - 如果使用 **Built-in** 下拉菜单中的分块方法，请确保它支持 PDF 解析，然后从 **PDF parser** 下拉菜单中选择 **MinerU**。
   - 如果使用自定义数据摄入管道，请在 **Parser** 组件的 **PDF parser** 部分中选择 **MinerU**。

要使用外部 Docling Serve 实例（而非本地进程内 Docling），请设置：

- `DOCLING_SERVER_URL`：Docling Serve API 端点（例如 `http://docling-host:5001`）。

当设置 `DOCLING_SERVER_URL` 后，RAGFlow 将 PDF 内容发送到 Docling Serve（`/v1/convert/source`，回退到 `/v1alpha/convert/source`），并摄入返回的 markdown/文本。如果未设置该变量，RAGFlow 将继续使用本地 Docling（`USE_DOCLING=true` + 已安装的包）行为。

:::note
所有 MinerU 环境变量都是可选的。设置这些值后，会在首次使用时为租户自动配置 MinerU OCR 模型。要避免自动配置，请跳过环境变量设置，仅从 UI 中的 **Model providers** 页面配置 MinerU。
:::

:::caution 警告
第三方视觉模型标记为**实验性**，因为我们尚未对这些模型在以上数据提取任务中的表现进行完整测试。
:::

### 电子表格解析器

电子表格解析器输出 `html`，保留原始布局和表格结构。如果数据集中没有电子表格，可以移除此解析器。

### 图片解析器

图片解析器默认使用原生 OCR 模型进行文本提取。如果已在 **Model provider** 页面正确配置，您可以选择替代的 VLM 模型。

### 邮件解析器

通过邮件解析器，您可以选择要从邮件中解析的字段，如**主题**和**正文**。解析器会从这些指定字段中提取文本。

### 文本与标记解析器

文本与标记解析器自动移除所有格式化标签（如 HTML 和 Markdown 文件中的标签），仅输出干净的纯文本。

### Word 解析器

Word 解析器输出 `json`，保留原始文档结构信息，包括标题、段落、表格、页眉和页脚。

### PowerPoint (PPT) 解析器

PowerPoint 解析器将 PowerPoint 文件的内容提取为 `json`，单独处理每个幻灯片，区分标题、正文和备注。

### 音频解析器

音频解析器将音频文件转写为文本。要使用此解析器，必须先在 **Model provider** 页面配置 ASR 模型。

### 视频解析器

视频解析器将视频文件转写为文本。要使用此解析器，必须先在 **Model provider** 页面配置 VLM 模型。

## 输出

**Parser** 组件输出的全局变量名称，可以被数据摄入管道中的后续组件引用。

| 变量名      | 类型              |
|------------|-------------------|
| `markdown` | `string`          |
| `text`     | `string`          |
| `html`     | `string`          |
| `json`     | `Array<Object>`   |
