# 什么是检索增强生成（RAG）？

自大语言模型（LLM）成为技术焦点以来，其处理通用知识的能力令人惊叹。然而，当问题转向企业内部文档、专有知识库或实时数据时，LLM 的局限性便显露无遗：它们无法访问训练数据之外的私有信息。检索增强生成（Retrieval-Augmented Generation，RAG）正是为解决这一核心需求而生。在 LLM 生成答案之前，它首先从外部知识库中检索最相关的上下文，并将其作为"参考资料"输入给 LLM，从而引导其生成准确的答案。简而言之，RAG 将 LLM 从"凭记忆作答"提升为"有据可依"，显著提高了其在专业领域和实时信息查询中的准确性与可信度。

## 为什么 RAG 如此重要？

尽管 LLM 在语言理解和生成方面表现出色，但它们存在固有的局限性：

- 知识静态性：模型的知识基于训练时的数据快照，无法自动更新，难以感知最新信息。
- 外部数据盲区：无法直接访问企业私有文档、实时信息流或特定领域的内容。
- 幻觉风险：在缺乏准确依据时，模型可能会为了维持对话流畅性而编造听起来合理但实际上是错误的答案。

RAG 的引入为 LLM 提供了实时、可信的"事实依据"。其核心机制分为两个阶段：

- 检索阶段：基于用户问题，从外部知识库中快速检索最相关的文档或数据片段。
- 生成阶段：LLM 将检索到的信息作为上下文，结合自身的语言能力，组织并生成最终答案。

这将 LLM 从"凭记忆说话"升级为"据文档说话"，显著增强了其在专业级和企业级应用中的可靠性。

## RAG 是如何工作的？

检索增强生成通过引入信息检索机制，使 LLM 能够利用实时、外部或私有数据源来生成更高质量的回答。其工作流程可分为以下几个关键步骤：

### 数据处理与向量化

RAG 所需的知识来源于各种格式的非结构化数据，如文档、数据库记录或 API 返回内容。这些数据通常需要先进行分块，然后通过嵌入模型转换为向量，并存储在向量数据库中。

为什么需要分块？直接对整个文档进行索引面临以下问题：

- 检索精度下降：对长文档进行向量化会导致语义"平均化"，丢失细节信息。
- 上下文长度限制：LLM 的上下文窗口有限，需要筛选出最相关的部分进行输入。
- 成本与效率：长文本的嵌入计算和检索成本更高。

因此，智能分块策略是平衡信息完整性、检索粒度和计算效率的关键。

### 检索相关信息

用户的查询同样被转换为向量，在向量数据库中进行语义相关性搜索（例如计算余弦相似度），匹配并召回最相关的文本片段。

### 上下文构建与答案生成

检索到的相关内容作为事实依据被添加到 LLM 的上下文中，LLM 最终生成答案。因此，RAG 可以被视为自动化上下文构建的"上下文工程 1.0"。

## 深入现有 RAG 架构：超越向量检索

工业级 RAG 系统远非"向量搜索 + LLM"那么简单，其复杂性和挑战主要体现在检索过程中。

### 数据复杂性：多模态文档处理

核心挑战：企业知识大多以包含文本、图表、表格和公式的多模态文档形式存在。简单的 OCR 提取会丢失大量语义信息。

先进实践：领先的解决方案（如 RAGFlow）倾向于使用视觉语言模型（VLM）或专门的解析模型（如 DeepDoc），将多模态文档"翻译"为富含结构和语义信息的单模态文本。将多模态信息转换为高质量的单模态文本已成为高级 RAG 的标准实践。

### 分块的复杂性：精度与上下文的权衡

简单的"分块-嵌入-检索"流水线存在固有矛盾：
- 语义匹配需要较小的文本块以确保语义焦点清晰。
- 上下文理解需要较大的文本块以确保信息完整且连贯。

这迫使系统设计在"精确但碎片化"与"完整但模糊"之间做出艰难权衡。

先进实践：领先的解决方案（如 RAGFlow）采用语义增强技术，例如构建语义目录和知识图谱。这不仅解决了物理分块带来的语义碎片化问题，还能基于实体关系网络发现跨文档的相关内容。

### 为什么向量数据库不足以支撑 RAG？

向量数据库擅长语义相似度搜索，但 RAG 需要精确且可靠的答案，这对检索系统提出了更高的要求：
- 混合搜索：仅依赖向量检索可能遗漏精确的关键词匹配（例如产品代码、法规编号）。混合搜索将向量检索与关键词检索（BM25）相结合，兼顾语义广度和关键词精度。
- 张量或多向量表示：为支持跨模态数据，采用张量或多向量表示已成为重要趋势。
- 元数据过滤：基于日期、部门、类型等属性进行过滤，是业务场景中的刚性需求。

因此，RAG 的检索层是一个以向量搜索为基础，但必须融合全文搜索、重排序和元数据过滤等能力的复合系统。

## RAG 与记忆：同源异流的检索

在智能体框架中，记忆机制的本质与 RAG 相同：都是根据当前需要从存储中检索相关信息。关键区别在于数据来源：
- RAG：面向用户预先提供的已有静态或动态私有数据（如文档、数据库）。
- 记忆：面向智能体在交互过程中实时生成或感知的动态数据（如对话历史、环境状态、工具执行结果）。
它们在技术底层（如向量检索、关键词匹配）上高度一致，可以看作是同一种检索能力在不同场景（"已有知识"与"交互记忆"）中的应用。一个完整的智能体系统通常同时包含面向固有知识的 RAG 模块和面向交互历史的记忆模块。

## RAG 的应用

RAG 在以下几个典型场景中已展现出明确价值：

1. 企业知识问答与内部搜索  
   通过将企业私有数据向量化并与 LLM 结合，RAG 可以直接返回基于权威来源的自然语言答案，而非文档列表。在满足智能问答需求的同时，天然契合企业对数据安全、访问控制和合规性的要求。
2. 复杂文档理解与专业问答  
   对于合同、法规等结构复杂的文档，RAG 的价值在于能够生成准确、可验证的答案，同时保持上下文完整性。其系统准确性在很大程度上取决于文本分块和语义理解策略。
3. 动态知识融合与决策支持  
   在需要综合多来源信息的业务场景中，RAG 演进为面向业务决策的知识编排与推理支持系统。通过多路径召回机制，融合来自不同系统和格式的知识，在生成阶段保持事实一致性和逻辑可控性。

## RAG 的未来

RAG 的演进正沿着几条清晰的路径展开：

1. RAG 作为智能体的数据基础  
   RAG 与智能体是架构与场景的关系。智能体要实现自主、可靠的决策与执行，必须依赖准确、及时的知识。RAG 为其提供了访问私有领域知识的标准化能力，是构建知识感知型智能体的必然选择。
2. 高级 RAG：用 LLM 优化检索本身  
   下一代 RAG 的核心特征是充分利用 LLM 的推理能力来优化检索过程，例如重写查询、摘要或融合结果，或实现智能路由。以 LLM 赋能检索的每个环节，是突破当前性能瓶颈的关键。
3. 迈向上下文工程 2.0  
   当前的 RAG 可被视为上下文工程 1.0，其核心是为单次问答任务组装静态知识上下文。即将到来的上下文工程 2.0 将以 RAG 技术为核心进行扩展，成为一个自动、动态地为智能体组装综合上下文的系统。该系统融合的上下文不仅来自文档，还将包括交互记忆、可用工具/技能以及实时环境信息。这标志着智能体开发从"手工作坊"模式迈入自动化上下文工程的工业化起点。

RAG 的本质是为大语言模型构建一个专用、高效、可信的外部数据接口；其核心在于检索（Retrieval），而非生成（Generation）。从解决私有数据访问的实际需求出发，其技术深度体现在对复杂非结构化数据的检索优化上。随着其与智能体架构的深度融合以及向自动化上下文工程的发展，RAG 正在从一项提升问答质量的技术，演变为构建下一代可信、可控、可扩展智能应用的核心基础设施。
